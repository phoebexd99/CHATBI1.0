# Excel / CSV 与 PostgreSQL 数据源 MVP

## 用户链路

1. 在 Live 首页 `/` 查看“接入数据 → 自然语言提问 → 获得业务结果”的完整流程；旧 `/data-sources` 地址保留为兼容入口。
2. 从三个入口中选择一种：上传 `.xlsx` / `.csv`、连接只读 PostgreSQL，或打开演示模板弹窗。数据集列表只在弹窗中显示，并先给出“选择数据 → 查看可问内容 → 自然语言提问”的步骤指引。
3. 文件入口接受不超过 10 MB 的 `.xlsx` 或 `.csv`；Excel 最多读取前 10 个工作表。
4. 后端把首个非空行识别为表头，推断日期、整数、数值和文本类型，并把字段自动标记为时间、指标、维度或标识，同时计算完整率、唯一值数量和样例值。
5. 用户在数据画像中确认或修正字段用途，也可以把含糊的上传文件名改成业务名称；保存后系统重新生成适合该数据集的问题建议。
6. 用户点击“选择并提问”。平台打开专注问数弹窗，问题输入、流式进度、结果、图表和解读都在弹窗内完成；首页继续只承担数据入口。当前选择通过 `?dataset=<id>` 保留可分享状态。
7. 查询引擎根据真实字段名、分类样例值和明确年月选择指标、分组与筛选条件，生成受控聚合 SQL，经动态表白名单和只读 SQLGlot 校验后执行；SQLite 文件源额外执行 dry-run，PostgreSQL 连接使用只读会话与语句超时。

PostgreSQL 入口接收主机、端口、数据库、Schema、只读用户名、密码和 SSL 模式。连接成功后只发现指定 Schema 内的普通表/视图、字段类型与少量分类样例，不复制业务明细到本地；问数时直接读取源库。请仍然在数据库侧创建权限最小化的只读账号，避免使用管理员账号。

内置 `demo` 数据集不会被替换。它继续使用认证指标目录、LangGraph、RAG/Wren 适配器和原有经营分析链路；上传文件使用隔离的数据集分析器，因此不会把未经治理的 Excel 字段伪装成认证业务指标。

## API

- `GET /api/datasets`：列出内置模板和本机已上传数据集。
- `POST /api/datasets/upload`：multipart 上传，字段为 `file` 和可选 `name`。
- `POST /api/datasets/connect/postgresql`：验证只读连接，发现指定 Schema 的表和字段，并在当前 API 进程中暂存连接。
- `GET /api/datasets/{dataset_id}`：返回工作表、字段画像和最多 8 行预览，不返回内部物理表名。
- `POST /api/datasets/{dataset_id}/model`：保存数据集业务名称和字段角色确认结果，并更新推荐问题。
- `POST /api/query` 与 `POST /api/query/stream`：请求体新增 `dataset_id`；缺省值为 `demo`，兼容原有调用。

## 存储与安全

- 原始上传文件不落盘，也不会进入 Git。
- 标准化数据默认写入仓库根目录、已被 `*.db` 规则忽略的 `chatbi_datasets.db`。
- 单表最多 100,000 行、100 列；查询最多返回 100 行。
- 每个上传表使用随机内部表名；SQL 只允许访问本次所选表，不允许 DDL、DML、注释、系统目录或危险函数。
- 前端渲染会转义单元格文本；服务端不执行 Excel 公式，读取的是已有缓存值。
- PostgreSQL 密码不会写入 Git、SQLite 元数据或浏览器存储；连接 URL 只存在于当前 API 进程内，API 重启后数据集会显示“需要重新连接”。
- PostgreSQL 连接带有只读会话、10 秒语句超时和约束后的 `SELECT` 校验，但生产环境仍必须依赖数据库只读角色、网络白名单和审计作为最终边界。

## 当前能力边界

已实现的是“未知单表或多工作表文件的自动画像 + 字段角色确认 + 单表聚合分析”，不是通用语义建模平台。当前可稳定支持记录数、求和、平均、最大/最小、按低基数字段分组、Top N、按月趋势，以及问题中出现的分类样例值和明确年份/月份筛选。尚未实现：

- 自动推断多工作表之间的主外键并执行跨表 JOIN；
- PostgreSQL 多表自动关系推断、JOIN 规划，以及 MySQL、SQL Server、ClickHouse 等连接器；
- 从任意口语中可靠推断数值区间、相对日期、同比/环比和多步归因；
- 上传数据的持久化生命周期、删除、版本、负责人和审核状态；
- 用户认证、租户隔离、RLS、PII 识别/脱敏与对象存储；
- 把上传字段发布为正式指标，或自动写入 pgvector / Wren 生产语义层。

下一阶段应增加一个“建模确认”步骤：建议表间关系、让用户确认日期/金额/主键字段，再把确认后的模型发布到受治理的 Analytics Mart；随后补齐数据库连接的加密凭据托管、连接池、认证/RLS、租户隔离和审计，并扩展 MySQL 等连接器。
